# Live Speech STT

Приложение для захвата **системного звука** (не микрофона) и распознавания речи
в реальном времени: Discord, Telegram/WhatsApp-звонки, YouTube, игры — всё, что
проигрывается через устройство вывода. Основная платформа — **Windows** (WASAPI
loopback, без дополнительных драйверов); есть и сборка для **macOS** (через BlackHole) —
см. раздел [macOS](#macos) ниже.

## Как это устроено

```
AudioCapture (WASAPI loopback, pyaudiowpatch)
      │  float32 mono @16kHz чанки
      ▼
StreamingVAD (webrtcvad + триггер/hangover)
      │  границы фраз: начало / конец речи
      ▼
UtteranceBuffer  →  SpeechRecognizer (faster-whisper локально, либо облачный провайдер)
      │  partial / final текст
      ▼
TextProcessor (пунктуация, склейка в предложения)
      │
      ▼
Qt-сигналы → UI (главное окно, Subtitle Mode, диагностика)
```

Захват и распознавание работают в отдельном потоке (`QThread` + `QThreadPool`), поэтому
интерфейс никогда не подвисает — даже если модель распознавания думает полсекунды.
`SpeechRecognizer` — абстрактный интерфейс (`livestt/stt/base.py`): чтобы заменить
движок распознавания, достаточно добавить новый класс и одну строку в
`livestt/stt/factory.py`, остальной код не меняется.

## Почему такой стек

- **PySide6** — нативный на Windows, тёмная/светлая тема, прозрачные/безрамочные окна
  (нужны для Subtitle Mode), системный трей, корректная многопоточность через сигналы/слоты.
- **pyaudiowpatch** — форк PyAudio с поддержкой WASAPI loopback. Даёт
  `get_loopback_device_info_generator()` — список всех устройств вывода как источников
  записи «того, что слышно», без обращения к микрофону.
- **webrtcvad-wheels** — тот же `webrtcvad`, но с готовыми wheel-файлами под Windows
  (не требует компилятора при установке).
- **faster-whisper (CTranslate2)** — Whisper с низкой задержкой, CPU (int8) и GPU/CUDA
  (float16), встроенная пунктуация, русский/английский/автоопределение языка «из коробки».
- **keyring** — ключ облачного API хранится в Windows Credential Locker, а не в
  settings.json открытым текстом.

## Требования

- Windows 10/11, 64-bit
- Python 3.10–3.12 (64-bit) — https://www.python.org/downloads/
- Для GPU-ускорения: NVIDIA-видеокарта + актуальные драйверы (CUDA подхватывается
  автоматически через ctranslate2, отдельно ничего ставить не нужно)

## Установка и запуск

```bash
install.bat
run.bat
```

`install.bat` создаёт виртуальное окружение `venv` и ставит зависимости из
`requirements.txt`. При первом запуске faster-whisper скачает веса выбранной модели
Whisper (по умолчанию `small`, ~500 МБ) с Hugging Face — нужен интернет один раз.

## Сборка .exe

```bash
build.bat
```

Результат: `dist\LiveSpeechSTT\LiveSpeechSTT.exe`. Это `--onedir`-сборка (не `--onefile`) —
так надёжнее запускаются тяжёлые бинарные зависимости (ctranslate2, Qt) и быстрее старт.
Иконка приложения (`assets/icon.ico`) вшивается в exe автоматически.

## Установщик для друзей (один файл, без Python)

Чтобы раздать приложение так, чтобы его можно было поставить обычным Windows-установщиком
(двойной клик → "Далее, Далее, Готово" → ярлык на рабочем столе), нужно:

1. Поставить бесплатный **Inno Setup 6**: https://jrsoftware.org/isdl.php
2. Выполнить по порядку:

```bash
install.bat
build.bat
build_installer.bat
```

Результат: `installer_output\LiveSpeechSTT-Setup-1.0.0.exe` — это и есть файл для друзей.
Он сам создаст ярлыки в "Пуск" и на рабочем столе, пропишет деинсталлятор в
"Установка и удаление программ", не требует прав администратора и Python на компьютере
получателя (весь Python и зависимости уже упакованы внутри).

## macOS

На macOS нет встроенного аналога WASAPI loopback, поэтому системный звук захватывается
через бесплатный виртуальный аудио-драйвер **BlackHole** — он появляется как обычное
"устройство записи", и приложение видит его точно так же, как Windows видит loopback-
устройство. Это тот же подход, что используют Krisp, OBS и другие подобные программы.

### Разовая настройка (один раз на компьютер)

1. Поставь **BlackHole 2ch**: https://existential.audio/blackhole/ (бесплатный .pkg).
2. Открой **Audio MIDI Setup** (Spotlight → "Audio MIDI Setup").
3. Нажми "+" внизу слева → **Create Multi-Output Device**.
4. Отметь галочками и свои обычные колонки/наушники, и **BlackHole 2ch**.
5. В Системных настройках → Звук → Вывод — выбери этот Multi-Output Device как
   устройство вывода по умолчанию (так ты продолжишь слышать звук, а BlackHole получит
   его копию для записи).
6. В самом приложении (Настройки → Устройство) выбери **BlackHole 2ch**.

### Установка и запуск

```bash
chmod +x install.sh run.sh build.sh
./install.sh
./run.sh
```

### Сборка .app для раздачи друзьям

```bash
./build.sh
```

Результат: `dist/LiveSpeechSTT.app`. Чтобы передать через флешку — просто скопируй
папку `LiveSpeechSTT.app` на флешку (или сожми в .zip перед копированием, macOS понимает
такой .zip из коробки).

**Важно:** приложение не подписано сертификатом Apple Developer (это платно, $99/год),
поэтому при первом запуске на другом Mac Gatekeeper покажет предупреждение
"приложение повреждено" или "не удалось проверить разработчика". Это нормально для
несигнованных .app — друзьям нужно один раз: правый клик на `LiveSpeechSTT.app` →
**Открыть** → подтвердить в диалоге (а не обычный двойной клик). После этого будет
запускаться как обычно.

Также при первом запуске macOS спросит разрешение на **Accessibility** (для глобальных
горячих клавиш) — это нужно один раз подтвердить в Системных настройках → Конфиденциальность
и безопасность → Универсальный доступ.

## Горячие клавиши (работают даже если окно не в фокусе)

| Комбинация | Действие |
|---|---|
| `Ctrl+Shift+Space` | Старт/Стоп |
| `Ctrl+Shift+C` | Копировать текст |
| `Ctrl+Shift+X` | Очистить текст |
| `Ctrl+Shift+S` | Сохранить расшифровку (TXT) |

## Настройки (окно Settings)

Устройство вывода, язык (авто/ru/en), движок распознавания (локально/облако), модель
Whisper, GPU, интервал промежуточного текста, чувствительность VAD, длительность тишины
для завершения фразы, тема, размер шрифта, запуск с Windows.

## Subtitle Mode

Компактное полупрозрачное окно поверх всех приложений: перетаскивается, изменяется
размер (угол снизу-справа), настраиваются прозрачность/размер шрифта/фон в Settings,
опционально Always on Top.

## Известные ограничения и что я не смог проверить сам

Эта сборка написана и протестирована в Linux-песочнице без Windows-железа, поэтому часть
вещей проверить напрямую не удалось — проверьте их первым делом на реальной машине:

1. **Сам захват WASAPI loopback** (`livestt/audio/capture.py`,
   `livestt/audio/device_manager.py`) — `pyaudiowpatch` ставится и работает только на
   Windows. Логика потока, пересчёта сэмплов и восстановления после обрыва устройства
   написана по документированному API pyaudiowpatch, но живого прогона на реальном
   устройстве вывода не было.
2. **Автозапуск с Windows** (`livestt/config/autostart.py`) — использует `winreg`,
   недоступный вне Windows.
3. **faster-whisper/ctranslate2 с реальными весами модели** — в песочнице не хватило
   диска (~250 МБ свободно) под ctranslate2 + веса модели. Сама обёртка
   (`livestt/stt/faster_whisper_engine.py`) и её сборка через фабрику протестированы без
   реальной загрузки весов; качество распознавания русской/английской речи нужно
   проверить на реальных файлах/потоке.
4. **Рендеринг GUI-виджетов** — PySide6 `QtCore` (сигналы/слоты/потоки) проверен
   реальными тестами; `QtWidgets` (отрисовка окон) в песочнице не стартует из-за
   отсутствия `libGL` в контейнере — это ограничение песочницы, не Windows (там Qt несёт
   свой software-рендерер).

Всё остальное — VAD (реальный `webrtcvad`), склейка текста/пунктуация, работа с
настройками, экспорт, оркестрация пайплайна через реальные Qt-потоки/сигналы, облачный
провайдер (реальный HTTP-запрос к OpenAI) — покрыто автоматическими тестами и прогонялось
по-настоящему (`tests/`, 46 тестов).

### Что обнаружилось и было исправлено в процессе тестирования

- В финализации фразы был жёсткий порог «не короче 300 мс», не связанный с настройкой
  VAD `vad_min_speech_ms` — короткие реальные слова («да», «ок») могли тихо не попадать
  в текст. Убрано.
- Реальный `webrtcvad` после громкой речи «отходит» к тишине не мгновенно — у него
  встроенный гистерезис порядка 300–400 мс. Это складывается с настройкой
  `vad_min_silence_ms` и формирует фактическую задержку до появления финального текста
  после конца фразы (поэтому промежуточный текст и важен — он обновляется ещё во время
  произнесения фразы, минимизируя ощутимую задержку).
